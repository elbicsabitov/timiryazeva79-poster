## 0. Главный разворот (читать первым)

Ресёрч рынка (бриф 06) честно показал: **«первый AI-музыкальный стриминг» — уже неправда и опасно.**
- **Spotify** (AI DJ / DJ X + Prompted Playlist, 2025) уже даёт «почему этот трек» + NL-стиринг + историю вкуса.
- **Yandex «Моя волна»** (ARGUS, 1500+ параметров) уже владеет mood/activity/language-диалами **и доминирует в Казахстане**.

Explainable autoplay, NL-стиринг и AI-плейлисты — это **table stakes 2025–26**, а не moat.

**Новое позиционирование:**
> «Музыка, которая действительно **ваша** — вы **видите и редактируете** свой вкус и **знаете, почему** играет каждый трек.»

Три реальных опоры (white space, который никто не отгрузил целиком):
1. **Twinr-профиль как видимый, редактируемый, делимый объект** (не чёрный ящик).
2. **AI-экскурсы по музыке** (дёшево, защитимо, PR-движок).
3. **Локальность**: Казахстан → русскоязычный СНГ; казахская/тюркская курация + data-sovereignty/trust-позиция против «российского» багажа Яндекса.

Монетизация — freemium + **вкусовая реклама** (mood/contextual, PII-light, KZ-комплаенс), но честно: ~70% выручки уходит правообладателям, ранний RPM низкий. Реклама — стратегическое преимущество, не быстрый кэш.

## 1. Слой данных и каталог — это БИЗНЕС, а не деталь (бриф 05)

🚨 **Лицензирование — узкое горлышко №1.** Легально стримить мажор-лейблы нельзя без master + composition (mechanical/performance) прав — шести/семизначные минимумы, недоступны до выручки. **KZ collective-rights система формально признана слабой** (CISAC/IFPI, ноя 2025) — не полагаться на неё.

Три пути (комбинируем):
- **(A) Music-as-a-Service агрегатор (7digital / MassiveMusic)** — держит сделки, даёт лицензированный каталог-API + доставку + роялти-репортинг. → **реальный продуктовый путь.**
- **(B) Spotify Web Playback SDK** — права остаются у Spotify. → **отлично для UX-демо/инвесторам**, опасно как бизнес (коммерция требует письменного одобрения, >95% апп-апрувов отклоняют).
- **(C) Собственный KZ/CIS + Creative-Commons каталог** — для дифференцированного, полностью управляемого seed-каталога (локальные артисты = community-moat).

**MVP-решение:** демо на **Path B** + **Path C** свой каталог СЕЙЧАС; **Path A + найм KZ IP-юриста параллельно** (это длинный шест).

## 2. Twinr — модель вкуса (бриф 01, 03)

Не «алгоритм», а **несколько векторов**:
- **Долгосрочный** (медленный EMA) — это **видимый профиль**, который показываем/редактируем.
- **Краткосрочный** (SASRec-style session state) — «здесь и сейчас», чтобы «сделай по-другому» сработало за 1–2 трека.
- **Контекст** (время/настроение/активность).

**Вектор трека:** `[CF ⊕ CLAP ⊕ metadata]`. **CLAP** (аудио+текст в одном пространстве) — рычаг №1: cold-start, «почему» и NL-стиринг становятся **одной и той же векторной операцией**. (Зеркалит Yandex My Wave.)

**Старт без нейронок:** ALS / item2vec-CF + musicnn + ε-greedy. Грейдим до SASRec / two-tower / Thompson, когда появятся данные. **Бутстрап на бесплатном Yandex Yambda (5B событий, CIS-релевантно).**

**Из онбординга в профиль (бриф 03):** «embed-then-decay» (Spotify-паттерн) — кодируем seed-выборы тем же пайплайном, что и тёплых юзеров; `α·онбординг + (1−α)·поведение`, α→0 за первые дни. Twinr-вектор = popularity-de-biased взвешенная сумма item2vec (love +2 / like +1 / dislike −1.5), down-weight по log(популярность), чтобы нишевые тапы доминировали. Храним **именованные seed'ы** для объяснимости.

**Резюме→вкус:** opt-in тёплый prior (LLM→персона→мягкие приоры, подсвечивают пузыри), НИКОГДА не ground truth; требуем экран-подтверждение; сырой документ выбрасываем, храним только производные теги; отдельный consent перед рекламой.

## 3. Рекомендательный движок (бриф 01)

**Двухстадийная воронка** (не «одна модель»):
1. **Retrieval** — ANN по вектору (кандидаты из каталога). pgvector до ~10M векторов → Qdrant/ScaNN дальше.
2. **Re-rank** — дешёвый GBDT-ранкер по фичам (контекст, свежесть, разнообразие).

**Скопировать Spotify BaRT напрямую:** «Explore-Exploit-**Explain**» — контекстный бандит совместно оптимизирует **(трек, объяснение, контекст)**. Строка «почему этот трек» — **first-class рука бандита**, выведенная из *реальной* причины ретрива, **никогда не пост-фактум выдумка**.

Подводные камни: skip≠dislike (градуированные затухающие награды), popularity-collapse без explore-квоты, per-skip re-rank <100мс, честность объяснений, CLAP лицензия/GPU-стоимость.

## 4. Слой стиринга — «скажи, и радио поменяется» (бриф 02)

**Паттерн CTRL-Rec** (arxiv 2510.12742): LLM судит «одобрит ли юзер по его запросу?» **на этапе обучения**, дистиллируется в эмбеддинги — каждый живой стир стоит **одной embedding-операции (~10–50 мс), не генеративного LLM-вызова** → держим реакцию радио <800 мс.

**Intent-компилятор:** каждое высказывание → типизированный `SteerOp` (hard filter | soft re-rank | embedding nudge | diversity boost | constraint) — самый дешёвый механизм, удовлетворяющий запрос. LLM **никогда не выбирает треки** (guardrail + стоимость).

**Память раздельно:** эфемерный **session-intent вектор** (каждый стир мутирует, «темнее» приземляется за 1–2 трека) vs durable **Twinr-профиль** (медленный EMA + confirmation-gate, чтобы тренировка не переписала вкус навсегда).

Технологии: **Text2Tracks** (генеративный retrieval с semantic IDs, +127% acc, Spotify Research) для prompt-to-playlist; **TalkPlay-Tools** (LLM-as-planner, Llama-3.2-1B класс) для чат-компаньона.

**Три поверхности стиринга над одним вектором:** редактируемый Twinr-профиль · mood/activity-диалы (Yandex) · свободный текст. Применять стир как **2–3-трековый transition-ramp** с novelty-floor, чтобы убить «whiplash». Тестировать русскоязычные критики отдельно.

## 5. Объяснимость + AI-экскурсы (бриф 04)

**Правило: retrieval-first, LLM-last.** Рекомендатель + музыкальная база знаний решают *что правда*; LLM только формулирует. Никогда не давать модели выбирать факты (влияния, даты, lineage) — там умирает доверие.

- **«Почему»-чипы сейчас** из attribute + collaborative сигналов («потому что вы слушали X»); добавить **KG-path объяснения** (PGPR/KPRN) как фирменную фичу. Counterfactual — v2.
- **«Город KG»** на MusicBrainz MBID + Wikidata/DBpedia (жанровая иерархия, даты) + AcousticBrainz (аудио-фичи) + **человеко-курируемый слой влияний**.
- 🚩 Wikidata `P737 "influenced by"` разреженный/субъективный — НЕ строить core-lineage на нём; опираться на **жанровый** lineage (Ishkur's 502 типизированных ребра); курировать artist-influence только для топ-артистов.
- **Анти-галлюцинация:** closed-world prompting + **NLI faithfulness gate** (DeBERTa) + cite-or-suppress перед выводом.
- **Туры:** KG планирует фактический костяк + трек-лист; LLM пишет только переходы. Прогрессивное раскрытие (чип → нарратив); дать юзеру **отвергнуть** причину → правит Twinr (scrutability = высшее доверие).

## 6. Система и MLOps (бриф 05)

```
Клиенты (web/mobile/TV/car)
  │  события: play/skip/dwell/like/steer
  ▼
Redpanda/Kafka → Flink (near-real-time)
  ├─► Feature store + Twinr profile store (online nudge + бандит, НЕ ретрейн)
  ├─► Embedding/Vector store (pgvector → Qdrant)  ──► Retrieval
  │                                                     │
  │                              GBDT Ranker ◄──────────┘
  ▼                                   │
LLM Gateway (стиринг→structured deltas, объяснения, чат)   ▼
  · small-vs-large routing · prompt/semantic cache (~90% экономии)   Next-track (precompute во время текущего → <100мс тривиально)
  ▼
Audio delivery / CDN (через MaaS-агрегатора — §1)
```

- **Свежесть Twinr** = online embedding nudge + бандит, не ретрейны.
- **LLM-гейтвей:** роутинг малых/больших + промпт/семантик-кэш; стиринг парсится в **структурированные дельты** к вектору.
- **GDPR:** персонализация на legitimate interest; **вкусовая реклама требует явного consent.** A/B через server-side GrowthBook.

**Самые жёсткие ограничения по приоритету:** лицензирование > свежесть профиля > стоимость LLM > consent-gated реклама.

## 7. Монетизация (бриф 06)

- **Freemium** (подписка) + **вкусовая реклама** (mood/contextual, «born from song elements» à la AdsWizz/SiriusXM), PII-light, KZ-комплаенс.
- Честная экономика: ~70% роялти-drag, низкий ранний RPM. Реклама — стратегическое преимущество, не ранний gusher.
- Защитимое = trust + локальность + данные steering-acceptance + community локальных артистов. Каталог/лицензии/prompt-UX — коммодити.

## 9. Открытые решения для Эльбика (ранжировано)

1. **Каталог/лицензии** — Path B-демо сейчас + начать переговоры Path A агрегатора + нанять KZ IP-юриста. Это длинный шест: стартовать НЕМЕДЛЕННО, параллельно билду.
2. **Позиционирование** — принять разворот с «первый AI» на «музыка, которая ваша: видишь/правишь вкус, знаешь почему». (Юр-риск ложного «первый».)
3. **Beachhead** — Казахстан → СНГ; локальная/казахская курация как moat против Яндекса.
4. **Стек данных** — бутстрап на Yambda; CLAP как ядро вектора (GPU-бюджет).
5. **Реклама** — да, но Ф3, consent-gated; не ждать раннего дохода.

> Прототип (Ф0) уже демонстрирует §2–5 на уровне UX. Реальный движок — Ф1+. UI/UX-направление (как сделать AI «присущим сайту») — отдельный синтез `UX-DIRECTION-gorod-fm.md` (ресёрч в работе).
