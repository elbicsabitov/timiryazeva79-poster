## 0. One-page

**Vision.** Город ФМ — AI-driven музыкальный стриминг, где рекомендация не чёрный ящик: каждый трек **объяснён поведенчески**, вкус правится **разговором и одним тапом**, а сам профиль (**Twinr**) — **видимый, редактируемый, делимый объект**.

**North-star.** «Ты видишь свою логику и можешь её поправить — **даже реклама твоя**.» Доверие = **FIDELITY**: показанное объяснение = реальная причина ретрива/реальный вектор. Это единственная грань между прозрачностью и маркетингом. *(Импликация a11y: «видишь свою логику» обязано работать и для незрячих — вектор `#/taste` нуждается в текстовой AT-репрезентации, иначе north-star ломается для screen-reader. См. §10.)*

**Wedge (что Яндекс/Spotify не скопируют быстро).** Не «AI-радио» (это table-stakes 2025–26: Spotify DJ X, Яндекс ARGUS уже дают «почему» + NL-стиринг). Wedge = **связка трёх**, которую никто не отгрузил целиком: (1) видимый редактируемый Twinr-вектор, (2) **seamful «Исправь причину»** — steering ЧЕРЕЗ объяснение, (3) **reason_tag corpus** — датасет ОБЪЯСНЁННЫХ предпочтений, который конкуренты не соберут ретроспективно (у них нет интерфейса сбора). Их позиционирование («магия за кадром») структурно мешает им скопировать — им пришлось бы перестроить бизнес-модель.

**Рынок = Москва / РФ.** Следствие (ARCHITECTURE §0): локальность-как-moat **исчезает** — это домашнее поле Яндекса; казахский орнамент и KZ-data-sovereignty убраны из позиционирования. Head-on с «Моей волной» сложен → дифференциация должна быть резкой и **видимой на каждом экране**.

**Во что метим («лучший сервис»).** Не «ещё одно музыкальное приложение с красивыми плитками», а **единственный сервис, где петля доверия замкнута и видима**: услышал трек → увидел честное «почему» → отверг причину одним тапом → профиль и волна пересчитались на глазах → следующее «почему» цитирует твою правку. Этот цикл (explain → reject → edit → steer → newExplain) сегодня в прототипе разорван на 3 острова (TwinrWhy / GorodTaste / GorodProfile пишут и читают `gorodfm_rejected` несогласованно). Замкнуть его — и есть «лучший сервис». Всё остальное (recap, стрики, открытие, монетизация) — поверхности ТОГО ЖЕ цикла, не отдельные фичи.

### 1.1 Навигационная модель (3-tab + deep-dive + overlay + поиск)

Железное правило (AUDIT §2, UX-DIRECTION §1, IA-измерение): **3 вкладки. «Открыть» = НЕИЗВЕСТНОЕ, всё известное → «Мой вкус».** Смешивать архив и discovery — главная ошибка стриминга (Sonos: 3 дублирующие browse-вкладки = ~$500M провал).

```
ВОЛНА (#/home)          МОЙ ВКУС (#/taste)             ОТКРЫТЬ (#/discover, alias #/podborki)
= радио, пассив         = профиль+архив, актив-Я        = неизведанное, актив-МИР
• now-playing+«почему»  • редактируемый вектор          • РАЗГОВОР (семант. запрос)
• steer (4 канала)      • контекст-старты (051✓)        • карта вкуса (кластеры)
• between-track (048✓)  • Twinr-recap → #/recap         • «рядом с твоим вкусом»
• контекст-чип          • стрик «дни роста модели»      • редакторский ряд (быв. Подборки)
                        • Сохранённое (быв.Изб.+Медиа)
```

- **Deep-dive (push, НЕ таб):** `#/artist`, `#/track` — открываются из ЛЮБОЙ карточки трека. Back + mini-player, без тупиков.
- **Overlay:** `#/recap` (входит из «Мой вкус»), чат-док (демоут — открывается ИЗ inline-affordances плеера), `wave-dials` / `why-pop` (bottom-sheet).
- **Поиск (built → rework, НЕ to-add).** `.topbar-search` УЖЕ существует и wired (CSS @334, элемент @7141 `aria-label="Открыть поиск"`, surface-адаптеры tv@6052 / carplay@6191). **Единица работы:** проверить, ведёт ли поле к СЕМАНТИЧЕСКОМУ запросу («осенний дождь за окном»), а не к generic-фильтру; если generic — апгрейд существующего поля до conversational, переиспользуя `Q2V` @13412 (тот же intent-router). Тап по узлу карты вкуса заполняет это же поле = «две двери в одно». НЕ добавлять новую иконку.
- **Anti-pattern, который держим:** skip НЕ самый заметный контрол (иначе UI учит скипать → убивает reason_tag corpus). Лайк/steer первичны, skip вторичен.

## 2. Сквозные user-flows

Все flows возвращаются на одну из 3 вкладок через mini-player; нет тупиков.

**A. Первый запуск (cold-start «модель за 7 треков»).** Запуск → (fix P0 W0, см. §7) cold-start ветка ДО `savedRoute`-резолва: пустой профиль → `#/onboarding`, НЕ `#/map`. Три входа в онбординг: (1) пузыри (дефолт; гравитация к центру, реал-фото артистов), (2) **резюме→музыка — УЖЕ построено** (@9578–9628, VISION#7), (3) **стриминг-import-seed — NOT built, новая работа** (Last.fm/Spotify/Яндекс export, opt-in, экран-подтверждение, сырое выбрасываем). После ~7 сигналов — **прерывание на «Вот как я тебя понял за 7 треков»** (NOT built — GorodOnboarding @12734 сегодня собирает сигнал, но НЕ показывает редактируемый мини-вектор): мини-Twinr-вектор + поведенческая причина под каждой строкой («дослушал Молчат Дома 2× → пост-панк↑») + кнопка «Поправь» = первая демонстрация управляемости (видимая версия TikTok-aha). → `#/home`, первая волна, «почему»-чип виден сразу.

**B. Daily-driver (утренний якорь).** Пуш 7:45 несёт ПОВЕДЕНЧЕСКУЮ причину в тексте: «Утро. Собрал 40 мин на 85 BPM — как ты любишь по будням. Начну мягко.» Тап → `#/home` с контекстом. На `#/taste` контекст-старт «Утро/День/Вечер/Ночь» (051✓) уже выбран по времени (suggest, не auto-drive) → тап реально сдвигает session-вектор + квитанция. Слушает → видит «почему» → при несогласии «не моё» → волна пересчёт. ≤2 релевантных пуша/нед.

**C. Weekly (recap-петля + виральность).** Вс 19:00 мягкий пуш → `#/recap`: дельта-герой «+darkwave −арена-рок» + 1 открытие с «почему» + «Скопировать»/PNG для Stories + micro-CTA «не согласен? поправь» → `#/taste`. Шер = главный органический канал (Wrapped: 500M шеров/24ч), но дифференциация — через ПРИЧИННОСТЬ, не числа.

**D. Re-engagement (win-back).** 3 дня без сессии → антропоморфный «3 дня тишины — Волна не понимает, изменился ли твой вкус. Зайди, проверим» (приглашение к управляемости, НЕ guilt «ты пропустил 47 новинок»). Event-пуш «[Артист] выпустил трек. Добавил в твою волну на завтра» ≤10 слов (высший CTR). Приоритет: event > re-engagement > recap > утренняя.

**E. Конверсия в premium.** Premium-фича = **«живой профиль» + экспорт Twinr** (НЕ «без рекламы» — это commodity; ad-tier первичен, §6). Триггеры: после первого recap-шера, после N правок вектора, на `#/profile` («экспортируй свою модель / расширенный timeline эпох»). Реклама на free финансирует per-stream лицензии; premium-first = anti-pattern (нулевая позиция перед лейблами без массового слушателя).

## 3. Per-surface UX/UI направление

**Волна / плеер (`#/home`).** Что: пассивное радио, главный экран. Элементы: context-карта (схлоп → чип «Сменить»), artwork+ambient-волна (волна = СЛОЙ снизу, не перекрывает лицо), 1-строчная поведенческая «почему» (тап → L2), `❤ [—track—] ✕ + [Steer]`. Wedge: «почему» always-on + steer одним тапом + видимая квитанция. Anti-slop: ❌ fake-обложка (asset-wall → art-tint), ❌ skip-prominent, ❌ orb. Between-track (048✓): transition-card «DJ объявляет следующий» (FLOW @13553), не спиннер.

Элементы: группы Жанры/Настроения/Артисты/Эпохи с +/−/pin (@13136), волна-canvas (`#taste-wave`, рендерится только тут — @13044), taste-sponsor, контекст-старты (051✓), вход в recap, строка стрика, Сохранённое. **Трек (`#/track`, gated 047 — ГЛАВНЫЙ).** Что: высший explainability-момент (наш ответ Pandora «Why did you play this song?», честнее). Элементы: art-tint hero (монограмма на однотонной плашке) → центр «Почему играет» (полное L2: «Tempo 112 BPM», «женский вокал 7× дослушал», «настроение→ты выбрал Спокойно») + «Исправить причину» → вектор трека (BPM/энергия/вокал/акустика через волна-мотив) → соседи по атрибутам с ПОЧЕМУ-сосед («тот же темп»). ## 4. AI / RecSys / Explainability архитектура

**Backbone (ARCHITECTURE §2–6).** Twinr = НЕ алгоритм, а несколько векторов: долгосрочный (медленный EMA = видимый профиль) + краткосрочный (SASRec-style session-intent) + контекст. Вектор трека `[CF ⊕ CLAP ⊕ metadata]`; **CLAP** = рычаг №1 (cold-start + «почему» + NL-стиринг = одна векторная операция). Двухстадийная воронка: retrieval (pgvector ANN → Qdrant) → re-rank (GBDT). **BaRT explore-exploit-explain:** строка «почему» = first-class рука бандита из РЕАЛЬНОЙ причины ретрива, никогда пост-факт.

**Steering — один session-вектор, типизированный SteerOp (CTRL-Rec).** Каждое высказывание → `SteerOp{hard_filter|soft_rerank|embedding_nudge|diversity_boost|constraint}` = одна embedding-операция ~10–50мс, НЕ генеративный LLM на hot-path (<800мс steer-to-next). 4 канала прототипа (TwinrWhy reject @13326, WaveDials @13275, per-track, текст-чат) сегодня **decoupled** — каждый сам дёргает `TwinrWave.bump()` без общего intent-объекта. Целевое: единый `window.GorodWave.steer({source,delta})` → (1) анимирует волну, (2) показывает квитанцию, (3) nudge микро-дельту в «Мой вкус». **Память раздельно:** эфемерный session-вектор vs durable Twinr (EMA + confirmation-gate, чтобы одна атипичная сессия не переписала видимый профиль навсегда). RU-first router = correctness-требование (тест «сделай темнее», «меньше реп», «что-то под дорогу»).

**reason_tag moat — единственный незаменимый ров (и самый недостроенный).** Сегодня каждый reject/like/skip/dial/text — labeled preference pair — **генерится и выбрасывается** (TwinrWhy пишет только массив facet-id в `gorodfm_rejected` @13302). Headless-эмиттер `logEvent{track_id, reason_id, reason_text, action, surface, session_vector_snapshot, ts, schema_v, is_synthetic}` в append-only store. **Строится СЕГОДНЯ на scripted-данных** (session_vector = stub сейчас) — схема и привычка сбора стартуют немедленно. **🔑 Чистота рва (правка по ревью):** scripted-стадия ОБЯЗАНА писать `is_synthetic: true` + `schema_v`, чтобы при переходе на реальный бэкенд (Ф1) stub-векторы фильтровались и НЕ загрязняли единственный незаменимый датасет «реалистично выглядящим мусором». Пул GOROD-055 в P0-prototype-задачи (см. §7).

**Reason Provenance Contract + fidelity-аудит.** North-star «объяснение=реальный вектор» сегодня нефальсифицируем (ничто не связывает `REASONS` @13297 с причиной ретрива). Целевое: каждый трек → типизированный provenance-объект `{cause: cf_neighbour|clap_attribute|steer_op|context, evidence, contribution_weight}`; why-строки **темплейтятся из provenance, closed-world, никогда не free-generated**; CI-аудит проверяет, что заявленная причина в top-k реальных contributions (метрика fidelity-violation-rate); NLI-gate (DeBERTa) cite-or-suppress только на narrative-слое.

**Стадии (ARCHITECTURE §8 — каждая зарабатывает свои данные).**
- **Ф0 (есть): прототип** — scripted AI, продаёт визию.
- **Ф1 Licensed-demo MVP** — Path B (Spotify SDK для UX-демо) + Path C свой CC/KZ seed; item2vec-CF + musicnn + ε-greedy; CLAP-эмбеддинги; «почему» из реальной причины; видимый/редактируемый Twinr; ручные mood-диалы. **Не начинать с нейронок** (нет данных). Бутстрап на Yambda-5B.
- **Ф2 Own-rights beta** — Path A агрегатор (юрист в Ф1); Redpanda+Flink; pgvector+GBDT; online Twinr nudge; CTRL-Rec intent-компилятор; NLI-gated; KG v1.
- **Ф3 Scale** — SASRec/two-tower; Qdrant; BaRT-бандит; Text2Tracks (prompt-to-playlist); вкусовая реклама (consent).

**Headless-бэкенд vs клиент.** Бэкенд держит: embedding-пайплайн, ANN-индекс, GBDT/SASRec ранкер, BaRT, reason_tag append-only store, durable Twinr EMA store, SteerOp embedding-op, Provenance Contract + fidelity-аудит, LLM-gateway (small-vs-large routing + semantic cache, для async DJ-комментария). Клиент: now-playing + provenance-темплейченный why-чип (НЕ LLM), захват+эмит всех событий, optimistic steer UI с reconciliation, локальный prefers-reduced-motion + AA. **Precompute next-track + provenance во время текущего трека** (<100мс тривиально; transition-card 048 = перцептивное прикрытие). **LLM запрещён на per-skip/per-steer пути** (только чат-компаньон + async DJ + prompt-to-playlist).

## 6. Монетизация / Лицензирование / Moat / GTM

**Монетизация (порядок).** **Ad-tier первичен** — taste-targeted audio CPM $8–15 vs $2–4 non-targeted; реклама = единственная поверхность ПОКАЗАТЬ «даже реклама твоя» (taste-sponsor @13180 + «меньше рекламы» @13221 уже built). Premium через 6–12 мес = «живой профиль» + экспорт Twinr (фича, НЕ «без рекламы»). B2B taste-ads через кабинет «Большой Цифровой» (margin >60%). **Честное измерение** = Contextual Completion Rate (taste-match vs non-match) + confidence-score рекламодателю РЯДОМ (не прятать — AdTech прячет; мы продаём прозрачность измерения = тот же тезис, что explainable-ad юзеру) = переключатель бюджетов из Яндекс.Аудио/VK.

**Лицензирование (без экзистенц-риска).** Стадия 0 демо = CC (Jamendo/FMA/ccMixter) → Стадия 1 seed = **MERLIN** (≈15% инди одним договором, $0.003–0.005/stream, без авансов) + 2–3 куратор-лейбла → Стадия 2 после PMF = мажоры. **🚩 РФ-специфика (не в доках):** публичное доведение требует РАО/ВОИС/НФМИ — отдельный legal-трек, НЕ покрыт MERLIN. **НЕ запускать на мажорах без лицензии** (Suno/Udio → иски). MERLIN стартовать НЕМЕДЛЕННО, РФ music-IP юрист на Ф1 (длинный шест). Path B (Spotify SDK) на РФ-2026 как бизнес-путь мёртв — только UX-демо.

**Moat = три рва из ДАННЫХ (не UI).** (1) **reason_tag corpus** — 6-мес датасет ОБЪЯСНЁННЫХ предпочтений, не собрать ретроспективно (чистота через `is_synthetic` на scripted-стадии). (2) **Twinr cross-product identity** → `taste_segment: post-punk_melancholic + urban-engagement` (first-party, без PII) в кабинет (УЖЕ в репо). (3) **explainable-ad как категория** + CCR/confidence как B2B-продукт. Единый **event-bus** (play/skip/dwell/like/steer/reason) питает все 4 контура; приоритет надёжности: **лицензии (роялти-репортинг — договорное обязательство) > свежесть профиля > LLM > consent-реклама**.

**GTM Москва.** НЕ head-on масс-рынок (Яндекс держит Плюс-бандлом — lock-in, не musical moat). Beachhead = меломаны, для кого непрозрачность = БОЛЬ (кто гуглит «как сбросить Мою волну») → качественные reason_tag → виральность через recap. Каналы: музыкальные Telegram. **PMF-метрика = «% сессий со steering», НЕ MAU.** Consent (152-ФЗ) как ВИДИМАЯ часть wedge: opt-in taste-ads, видимый taste_segment, отзыв одним тапом = «не строим теневой профиль за спиной как AdTech» — комплаенс становится фичей доверия.

### ОДНОЗНАЧНАЯ рекомендация «что строить следующим» (prototype-level, без бэкенда)
**ВОЛНА 0 целиком, затем GOROD-047a (Трек).** Обоснование: ВОЛНА 0 чинит 2 живых fidelity-бага (W1 reject-divergence + `Math.random()` недетерминизм) + кладёт moat-фундамент (reason_tag с `is_synthetic`) + убирает позорный first-launch (`#/map` через 3-правочный router-fix) — всё low-effort, high-impact, без gated-решений и без бэкенда. ## 9. Разрешение конфликтов между измерениями (явно)

**§9-A. КЛЮЧЕВОЙ конфликт: контекст-старты 051 «в 045-карусель на `#/home`» (core-radio агент) vs «на `#/taste` аддитивно» (SPEC-051).**
**ПОБЕДИЛ SPEC-051.** Доказательство — не только спека, но и **live-прототип: 051 УЖЕ отгружен на `#/taste`** (`window.GorodContext` @14101, `TwinrWave.setContext` @13056). Три причины победы: (1) **`#/home` не имеет волна-canvas вообще** — `startWave()` биндится только к `#taste-wave` (@13044). Положить контекст-старты на home обещало бы видимый сдвиг волны без волны = FIDELITY-нарушение; `#/taste` — ЕДИНСТВЕННАЯ честная поверхность. (2) Аддитивно: `#/home` (Figma 2174:422) не тронут байт-в-байт → gated-045 **не триггерится** → решение Эльбика «насколько ломать home» не форсируется. (3) `setContext` neutral-state = байт-идентичный текущий рендер до первого вызова → zero regression. Core-radio агент прав в МЕХАНИКЕ (контекст-ДО-запуска + реальный BPM-сдвиг + behavioral why-now), но НЕ в РАЗМЕЩЕНИИ. Резолюция: механика сохранена, размещение = `#/taste`. (Замечание core-radio «не 4-я панель, чтобы не плодить 3 конкурирующие steering-поверхности как Sonos» — учтено: контекст=ДО, диалы=ВО ВРЕМЯ, текст=точно, один вектор.)

**§9-B. Конвергентные находки → чёткие P0-prototype-задачи.**
- **reason_tag генерится-и-выбрасывается** (несколько агентов сошлись) → **GOROD-055-lite эмиттер** (ВОЛНА 0, с `is_synthetic`). reason_tag = единственный незаменимый ров; строить headless на scripted сейчас.
- **wedge = «3 разрозненных острова»** (TwinrWhy reject / GorodTaste vector / GorodProfile fidelity не образуют петлю) → подтверждено grounded: `#/profile`+`#/recap` читают `gorodfm_rejected`, `#/taste` НЕ читает. Цель — петля explain→reject→edit→steer→newExplain. → **W1 (P0)**.
- **GorodTaste игнорирует `gorodfm_rejected` = fidelity-баг** → **ГРАУНД-ПОДТВЕРЖДЁН**: `seed()`@13124 читает только `gorodfm_taste`@13127, нигде не читает REJ. → **W1 (P0, top-priority)**. `Math.random()`@13130 = недетерминизм → чинить в той же задаче.
- **de-purple волны** → **УЖЕ СДЕЛАНО** (0 вхождений `#8b5cf6`). Снято из P0. **Warmth @13035 жива и корректна — мёртвого кода для cleanup НЕТ** (раннее утверждение черновика снято как фабрикация).
- **W6 anti-fidelity hard-gate + дедуп data-model** → после W1 у GorodTaste/Profile/Recap одна модель фактов (Profile/Recap уже byte-identical); расширить на GorodTaste = дедуп будущих расхождений.

**§9-C. Прочие.** Steering-унификация: 4 канала сейчас decoupled (каждый сам `bump()`) → один `GorodWave.steer` = ВОЛНА 1 рефактор (W2 кладёт первый кирпич — provenance последней правки). Recap cadence: weekly в «Мой вкус» + 1 пуш вс vs annual «Распаковка»-аналог — разная интенсивность сохраняет habit И эксклюзив (не конфликт, два режима). **Поправки fidelity самого блюпринта (адверсариал-ревью):** поиск и резюме-импорт были ошибочно предложены как «новое» — оба built; warmth-cleanup был фабрикацией; carplay-обоснование route-cleanup мислоцировано — всё исправлено выше, чтобы сам документ был fidelity-консистентен (нельзя продавать «показанное=реальное», будучи неточным к прототипу).

## 10. Перфоманс + Доступность как wedge-измерение (P2, новое)

Задача требовала «все измерения на Карпати-уровне». A11y/perf был раскидан по §5 и пропущен как срез — добавлен явно. Это не косметика: **a11y напрямую держит north-star.**

**10.1 Доступность (a11y) — прямое следствие north-star.**
- **Вектор `#/taste` обязан иметь текстовую AT-репрезентацию.** Волна-canvas `aria-hidden` @9647 → невидима для screen-reader → для незрячего юзера «видишь свою логику» НЕ работает = прямое противоречие тезису. Целевое: вектор (Жанры/Настроения/Артисты/Эпохи + %) + каждое «почему» доступны как структурированный текст/list для AT; canvas остаётся декоративным `aria-hidden`, но рядом — semantic-summary. **Приоритет P2, но обязательно для консистентности wedge.**
- Лок-токены уже есть (≥44px touch-target, focus-visible 3px, `prefers-reduced-motion` → static frame @13048/13059). Держать на ВСЕХ новых surface (Трек/Артист/карта вкуса).
- why-pop / steer-квитанции → `aria-live` (юзер слышит «убрал X — пересчитал»).
- i18n: сейчас RU-only — отметить как осознанный scope (рынок Москва), не баг; но не хардкодить строки в JS, держать в одном словаре под будущий beta.

**10.2 Перфоманс-бюджет (single-file ~14k строк).**
- **TTI:** один HTML/JS-файл растёт → измерить parse/exec на mid-tier Android; при деградации — разнести на чанки в Ф1 (прототип может остаться single-file).
- **Canvas / RAF:** волна = `requestAnimationFrame`-loop (@13042). **RAF обязан паузиться вне видимости** (`#/taste` не активна / `document.hidden`) — сейчас `stopWave()` @13051 есть, проверить, что он вызывается на route-уход и `visibilitychange`. Бюджет: целевой FPS на low-end mobile без drain батареи.
- **AnalyserNode fftSize 2048** (Ф1+): замерить CPU-cost на low-end; деградация-режим = вернуться к CSS-breathing при низком FPS (graceful).
- **Precompute next-track + provenance** во время текущего трека (<100мс) — transition-card 048 = перцептивное прикрытие; не блокировать UI-thread на steer.
