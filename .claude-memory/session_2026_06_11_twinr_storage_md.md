## Решения и почему

- **Перестройка всей секции под прод, а не только «пара кнопок»**: скрины = бриф (она их прислала именно для контекста); Костик берёт кнопки из актуального окружения, а наш файл остаётся source of truth.
- **Конвертер per-row, не в upload-карточке**: операция над конкретным существующим файлом; вторая точка входа возникает сама после живой загрузки.
- **Проекты в дропдауне** — реальные их сущности (Аудио Метрика / Большой Цифровой / CRM Турбо), антигаллюцинация.
- **Двухшаговая модалка** (convert → choose) дословно следует её ТЗ «ПОСЛЕ преобразования пусть пользователь сам выбирает».
- **Дубль архива клиентке не отправлять** без явного повторного подтверждения — против шума в клиентском чате.

- **Chrome MCP: navigate на тот же URL = no-op hash-навигация** — после пересборки standalone обязательно `reload ignoreCache`, иначе тестируешь старый билд (потерял на этом один цикл диагностики).
- Локальная telethon-сессия лочится параллельными скриптами (sqlite) → серверная сессия `/opt/mama-helper` как fallback для чтения и отправки.
- upload_file MCP не достаёт hidden `<input type=file>` (нет в a11y-дереве) → DataTransfer+dispatchEvent('change') честно тестирует всё после OS-диалога.
